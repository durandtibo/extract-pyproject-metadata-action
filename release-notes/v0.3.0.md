# v0.3.0

`v0.3.0` is a breaking release: the action does less and is simpler. Compared with `v0.2` (which only had the inputs `pyproject-path` and
`extra-values` and the outputs `name`, `version` and `extras`) everything below is new; the
tables list what the development version of `v0.x` had and what replaces it.

Pin the exact tag, `uses: durandtibo/extract-pyproject-metadata-action@v0.3.0`. No `v0.3` tag is
moved to a later release: a tag never changes after it is published.

## Inputs

5 inputs: `pyproject-path`, `extra-values`, `dependencies`, `python-candidates`, `strict`.

| Removed                   | Replacement                                                                                                                    |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `fail-on-missing`         | A requested dependency that is not found is a warning (`dependency '...' not found`) and `null`; `strict: "true"` fails on it. |
| `fail-on-dynamic-version` | A dynamic version is a warning; a release job uses `strict: "true"`.                                                           |
| `resolve-dynamic-version` | None. Ask the build backend (`python -m build`, `hatch version`, `python -m setuptools_scm`).                                  |
| `step-summary`            | None. The warnings and the error are `::warning` and `::error` annotations, which GitHub lists on the run page; no job summary is written. |
| `installer`               | Nothing is installed: `packaging` is vendored.                                                                                 |
| `python-executable`       | The action uses `python3`, or `python`, from `PATH`; choose the version with `actions/setup-python`.                           |

## Outputs

12 outputs and `json`: `name`, `normalized-name`, `file-name`, `version`, `normalized-version`,
`requires-python`, `python-versions`, `python-min`, `python-max`, `extras`, `groups`,
`dependency-specifiers`, `json`.

| Removed                                                                                                                                         | Replacement                                                                                                         |
| ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `description`, `readme`, `license`, `license-files`, `authors`, `urls`, `keywords`, `classifiers`, `scripts`, `build-backend`, `build-requires` | Read the field with `tomllib` in the workflow. The fields are no longer read nor validated.                         |
| `project-dependencies`                                                                                                                          | `dependencies: '["numpy"]'` for the packages that the workflow cares about.                                         |
| `python-matrix`                                                                                                                                 | `python-versions`: `matrix: { python-version: ${{ fromJSON(...python-versions) }} }`.                               |
| `dependency-requirements`                                                                                                                       | `fromJSON(...json).dependency_requirements`, whose items have a new `source` (`project`, `extra:<n>`, `group:<n>`). |

New: `file-name`, the name as written in the file names of wheels and sdists (`my_package`).
`normalized-name` (`my-package`) is for an index and `pip install`, not for file names.

## Behaviour

- A package declared in several places with different specifiers no longer warns; the plain
  name returns the first requirement of the search order.
- An invalid or dynamic `[project].dependencies`, extra or group is reported when `dependencies`
  asks for a lookup, not on every run: without a lookup the requirements are not read.
- The SPDX license warning and the output size warning are gone, with the outputs they were about.
- `python-candidates: ""` is the default list.
- Every error is `<field>: <problem>` (`[project].version: not a valid PEP 440 version: '1.x'`, `strict: must be 'true' or 'false', got: 'yes'`, `pyproject-path: not a file`). Errors and warnings no longer contain the file name: the annotation carries it (`::error file=...`), and a local run prints `<file>: <message>`.
- Each warning has a stable `code` (`dependency-not-found`, `dynamic-version`, ...; the table is in the README). The `warnings` array of `json` holds `{"code", "message"}` items, the `::warning` annotation has `title=<code>`, and the `strict` error lists `<code>: <message>`. The two warnings about a dynamic `dependencies` and a dynamic `optional-dependencies` are one, `dynamic-dependencies`.
- The `warnings` array of `json` holds objects, not strings, and the messages have no file name: a workflow that matched a message tests the `code` (`fromJSON(...json).warnings[0].code`).
- Nothing else changes for a workflow that uses the action. The program that the action starts has no command line any more: it reads the inputs from `INPUT_PYPROJECT_PATH`, `INPUT_EXTRA_VALUES`, `INPUT_DEPENDENCIES`, `INPUT_PYTHON_CANDIDATES` and `INPUT_STRICT`, and prints the JSON when `GITHUB_OUTPUT` is not set.
- `json` has `schema_version` `3`.
- Linux, macOS and Windows runners are supported. Nothing is installed or downloaded.
